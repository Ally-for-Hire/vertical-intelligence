# Theory notes (v0, Boolean CBN)

Setting: bits x_t in {0,1}^B, actions a_t, each target bit y_j = x_{t+1,j} predicted from parent set P_j (|P_j| <= k) by a count table with the KT estimator
(p = (n1 + 1/2)/(n0 + n1 + 1)). Uncertainty at time n is the prequential code length L_n = sum_t -log2 p_t(y_t), scored before the update.

**T1 (fixed structure, regret).** For a fixed parent set of size p, L_n <= n * H(Y | X_P) + 2^p * (1/2 * log2 n + 1) + const (KT regret per table cell; Krichevsky & Trofimov 1981, standard).
Consequence: if the true parents are in P, per-tick uncertainty converges to the irreducible conditional entropy at rate O(2^p log n / n). *Status:* standard result, not re-derived here; the learned curves plateau, consistent but the plateau is not yet compared to the analytic noise floor (TODO).

**T2 (false-parent rate of the MDL gate).** Adding a candidate parent c to a target with p parents is accepted when the plug-in gain G (bits, over window W) exceeds log2(B_in) + 2^p * (1/2) log2 W.
If c is independent of the target given the current parents, 2 ln2 * G is asymptotically chi-square(1) (Wilks), so P(false accept per candidate) <= P(chi2_1 > 2 ln2 * pen).
For p=0, B_in~400, W=3000: pen ~ 14.5 bits, threshold chi2 ~ 20, P ~ 8e-6 per candidate; best-of-6 screened candidates and ~30 searches give ~0.1 false parents per independent target over a run, independent of how many distractors exist per target (the log2 B_in term pays for the search).
*Status:* asymptotic argument; observed ~12 false links among 26 independent variables at n=64 (0.5 per variable at variable level), same order of magnitude but NOT a tight confirmation (delta-bit dependencies and the 5 bits per variable blur the count). Needs a pure-noise-world test (TODO).

**T3 (resolution lemma, motivates continuous/quantum states).** If scalar v is coded by m thresholds plus a sign-of-change bit, a one-tick change smaller than the bin width w changes the code only when it crosses a threshold; otherwise only the sign survives. The mutual information between an action and a per-tick change delta << w is therefore at most the information in the sign bit, and a count-table learner needs ~w/delta times more ticks to see the effect through threshold crossings.
*Evidence so far:* steering->omega links found in only 1 of 3 action links at n=0; throttle->v (large change) found. Consistent, not yet isolated. Test: soft-bit encoding (classical continuous) vs Boolean on identical runs.

**L4 (gate monotonicity, on-window).** Each accepted parent strictly lowers the penalised in-window code length by construction. This says nothing about out-of-sample loss; the prequential curves are the out-of-sample check. Parents are never removed in v0, so a spuriously accepted parent stays.

## v2 additions (two-timescale model)
**T4 (sliding trust).** Awake, each neuron keeps S <- max(0, S + CE(y,p) - H(p)) and trusts permanent counts with weight g = 2^-S. If the neuron's predictions are calibrated, E[CE - H(p)] = 0 and S is a reflected zero-drift random walk [CORRECTED iteration 13: the earlier text said 'g stays O(1)'. That is false: a reflected zero-drift walk grows like sqrt(t), so g = 2^-S drifts towards 0 even on a calibrated stationary stream; this is consistent with the observed mean g of 0.3-0.5 on stationary streams]; under a persistent mismatch S grows linearly, g -> 0 exponentially, so fast counts take over; when predictions are good again S shrinks and g recovers (a two-sided CUSUM with no reset and no threshold). The learning rate 1/(1+n_eff), n_eff = g*n_permanent + n_fast, therefore falls on correct predictions and jumps up after a failure.
*Status:* change-detection mechanism verified; the calibration statement was false (see correction above) (exp I: post-change surprise 47.1 vs 54.9 bits/tick without it, 8 seeds, se ~1). **Not calibrated:** mean g sits at 0.3-0.5 even on a stationary stream (exp H), i.e. the statistic also counts the model's own missing structure. Open.
**T5 (sleep terminates and is consistent).** Sleep accepts only steps that lower D = (plug-in code length) + (complexity: 1/2 log2 N per table cell + log2(#inputs) per parent). Growth adds a parent set only if gain > its added complexity; pruning removes a set only if its loss < the complexity it frees (same formula; pairs tested because growth adds action x variable pairs jointly). Since D strictly decreases and is bounded below, the loop ends. *Found by experiment:* sleeping every ~10 ticks produced dozens of adds and removals per sleep (borderline parents near the MDL threshold flip as N grows) and ~100x the compute. My hypothesis that single-parent pruning was killing jointly-needed pairs was tested by adding pair pruning and **did not change the add/remove counts**, so it was not the cause (pair pruning is kept because it is consistent with how growth adds sets, but it is not shown to matter). What fixed the cost was the doubling schedule (T6).
**T6 (amortised sleep).** Sleeping only when the history has doubled keeps total sleep cost within a constant factor of the cost of one full-history pass, i.e. O(T) overall; flat awake progress (BIC) gates it. Exp H: this self schedule reached the same causal-variable uncertainty as sleeping every 250 ticks (14.2 vs 15.1 bits/tick) with ~6% of the sleep compute.
**Importance rate (derived):** alpha_v = 1/(1+m_v), m_v <- (m_v+1) * 2^-excess, where excess is the Gaussian surprise of the new importance measurement against p with variance p(1-p)/(m+1). First sleep: m=0, alpha=1 (fully volatile); consistent measurements shrink alpha; an inconsistent one cuts m and raises alpha again.

## Rigor phase (2026-10-22)
**T7 (the soft gate is a learning-rate and re-initialisation, derived).** A gated input enters the first layer as p_i x_i, so the effective weight row is u_i = p_i W1_i and dL/dW1_i = p_i dL/du_i. Adam's step m_hat / (sqrt(v_hat) + eps) is invariant to multiplying a parameter's gradient by a constant (up to eps). Hence after the gate switches on, du_i = p_i * (the Adam step an ungated net would take on u_i): the gate is equivalent to re-initialising u_i = p_i W1_i at the switch and training row i with learning rate p_i * lr. Exceptions: Adam's eps, and a transient while the moments still hold pre-switch gradients (v decays with rate 0.999, ~1000 ticks). Consequence: a low-p input is not removed; it is learned p times more slowly and starts p times smaller. That is why false negatives are cheap, and why the gate can beat a hard mask. Status: **SUPPORTED by pre-registered test** (P6 passed: paired difference +0.004 +- 0.0015, per-world correlation 0.996). The added guess that the learning-rate half carries the effect (P7) FAILED: each half alone gives ~20% of the gain, both together ~100%.

**T8 (context accuracy bound, derived iteration 38).** If a learner routes each situation to one of several specialists, and a correctly routed situation has error E_r while a misrouted one has error E_w, then total error = a E_r + (1 - a) E_w for routing accuracy a. Staying within a factor m of perfect routing requires (1 - a) <= (m - 1) E_r / (E_w - E_r). In the P6 world E_r ~ 0.009 and E_w ~ 1.4, so within 2x needs >= 99.4% accuracy; the measured 93.6% gives ~10x, as observed. Consequence: the more different the specialists' rules (larger E_w / E_r), the more the whole system's value depends on context identification, and hedging by averaging does not help when rules are incompatible. Status: fresh test (CTX2) PASSED qualitatively (cost of misrouting rises with rule contrast) and FAILED quantitatively when E_w is taken as the average wrong-part error (over-predicts x1.3-2.0). Refined T8': use E_nearmiss, the error of the parts actually chosen by mistake: context mistakes cluster at boundaries and pick neighbours, which are less wrong than average. CTX5 (iteration 59) check of the LINEAR relation: with the same parts, halving misrouting (6.4% -> 3.2%) halved the error ratio (9.84 -> 4.97, factor 1.98). CTX6: with routing at 99.5%, error is 1.3-1.4 x the perfectly routed parts, so 0.5% misrouting still costs 30-40%: the implied cost per misroute is large: solving 1.4 = a + (1 - a) x for x gives about 60-80 x the routed-part error here, against about 125 x implied by CTX5's memory router. The per-misroute cost is therefore NOT constant (the misroutes left after border asking are cheaper ones), so the linear T8 with one fixed E_w is only approximate, and the CTX5 'factor 1.98' match is partly coincidence between two routers with similar misroute types.
